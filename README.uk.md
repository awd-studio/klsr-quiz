# КЛСР — тренажер залікових питань

[English](README.md) · **Українська**

Офлайн-тренажер для підготовки до заліку за файлом «Залікові питання КЛСР» (модулі 1–3, 209 питань).
Працює як сайт на GitHub Pages або як **один HTML-файл**, який відкривається напряму в браузері — на телефоні й комп’ютері, без інтернету.

## Можливості

- **Набори питань:** «Модуль 1» (100) або «Загальний» (модулі 1–3, 209).
- **Режими:**
  - **Картки** — питання → «Показати відповідь» → «Знав» / «Не знав» (обидві кнопки одразу переходять далі; «Не знав» = помилка).
  - **Вибір варіанту** — 4 варіанти: правильний дослівно з файлу + 3 неправильні. Порядок варіантів щоразу випадковий (і перемішується заново, коли повертається пропущене питання чи тест продовжують).
- **Складність варіантів** (режим вибору): **складні** (за замовчуванням) — неправильні варіанти з файлу, що відрізняються від правильного кількома словами чи пунктами, як на заліку; **легкі** — неправильними стають відповіді на суміжні питання того ж модуля (та сама форма — визначення чи список подібної довжини, але помітно інший зміст). Для «кількох відповідей» зайві пункти теж беруться з суміжних питань.
- **Інші формати** — у режимі вибору близько **10%** питань раунду (округлено, щонайменше одне від 10 питань: 20 → 2, 30 → 3, 100 → 10) автоматично подаються в одному з форматів:
  - **Так / Ні** — «Чи правильне твердження, що…?»;
  - **Термін за визначенням** — дано визначення з файлу, треба обрати поняття;
  - **Кілька відповідей** — оберіть усі правильні пункти;
  - **Послідовність** — розставте пункти в правильному порядку (TLP, SMESC, METT-TC, EDIP тощо);
  - **Формулювання з білетів** — питання в тому вигляді, як на фото залікових білетів.

  Кожне питання в межах раунду з’являється лише один раз — або стандартно, або в іншому форматі, але не в обох. У «Загальному» наборі також не потрапляють разом питання з однаковим текстом у різних модулях (М1 №32 / М2 №4, М1 №73 / М3 №20). Після відповіді показується питання й відповідь дослівно з файлу.

- **Налаштування:** кількість питань — окремо для кожного набору (за замовчуванням «Модуль 1» — 20, «Загальний» — 30), допустима кількість помилок (5), швидке налаштування «як на заліку» (30 питань, від 10 помилок — незадовільно).
- **Пропуск питання** — пропущені показуються після решти питань з позначкою «пропущене».
- **Лічильник** правильних / неправильних; при досягненні ліміту — індикатор і вікно «Почати заново / Продовжити».
- **Результат:** відсоток, статус, оцінка за шкалою заліку (30–28 «відмінно», 27–24 «добре», 23–21 «задовільно», ≤ 20 «незадовільно»; для іншої кількості питань пороги масштабуються), список помилок із вашою та правильною відповіддю, «Повторити помилки».
- **Складні питання** — запам’ятовуються ті, на які відповіли неправильно; окремий раунд з головного екрана. Правильна відповідь у цьому раунді прибирає питання зі списку.
- **Збережені питання** — зірочка ☆ на картці питання або в списку помилок; окремий екран із переглядом відповідей, кнопкою «Прибрати» та раундом зі збережених.
- **Виключені питання** — значок ⊘ біля зірочки під час тесту прибирає питання з усіх майбутніх тестів (картки, вибір, складні, збережені). На його місце одразу стає інше питання набору, тож кількість питань не змінюється; якщо замінити нічим (усі питання вже в раунді або тест зі списку) — питань стає менше. Після виключення з’являється повідомлення з «↶ Скасувати виключення» (закривається × або само через 30 с); на екрані «Виключені питання» можна повернути будь-яке питання або всі.
- **Версія і «Що нового»** — у підвалі головного екрана; сторінка змін будується з [`CHANGELOG.md`](CHANGELOG.md).
- **Незавершений тест** зберігається — після закриття вкладки його можна продовжити.
- **Гарячі клавіші (десктоп):** картки — `Пробіл` (перевернути), `←`/`1` (не знав), `→`/`2` (знав); вибір — `1–4` або `А–Г`; Так/Ні — `1`/`2`; `Enter` — далі / перевірити; `S` — пропустити.
- **Тема оформлення:** перемикач на головному екрані — як у системі / світла / темна; вибір запам’ятовується і застосовується ще до першого відображення сторінки; зміна теми анімована (повзунок і розкриття колом).
- **Мої списки:** складні, збережені й виключені питання; кнопка «Очистити» з підтвердженням очищує всі три списки одразу.
- **Після відповіді** правильний варіант коротко «пульсує», а неправильно вибраний — «хитається». Сторінка прокручується так, щоб було видно правильний і вибраний варіанти; правильний завжди видно повністю й на ньому фокус (`Enter` — «Далі»). Змінити відповідь після вибору не можна.
- **Перехід до наступного питання** плавно прокручує сторінку до питання. Панель з лічильниками й прогресом закріплена вгорі.
- **Тривалість усіх анімацій і переходів — не більше 0,2 с** (перевіряється тестом); при `prefers-reduced-motion` анімації вимкнено.
- Адаптивний інтерфейс, доступність (ролі ARIA, керування фокусом).

## Точність даних

Усі питання та правильні відповіді — **дослівно з файлу**. Це перевіряє автоматичний тест [`tests/data/source.test.ts`](tests/data/source.test.ts): кожне питання і відповідь мають стояти під своїм номером у своєму модулі тексту PDF ([`source/questions.txt`](source/questions.txt)) у тому самому порядку. Порівняння ігнорує лише регістр, пробіли, апострофи та розділові знаки.

Виправлено три очевидні друкарські помилки PDF (зафіксовано в тесті):

| Питання | У PDF     | У застосунку |
| ------- | --------- | ------------ |
| М1 №16  | «е віра»  | «Це віра»    |
| М1 №27  | «свїх»    | «своїх»      |
| М1 №47  | «вливати» | «впливати»   |

Також прибрано артефакти розриву рядків PDF («обов’ язків» → «обов’язків») і крапки з комою в кінці пунктів.

Твердження «Так/Ні» сформульовано лише там, де відповідь однозначно випливає з файлу. Неправильні варіанти вигадані й навмисно схожі на правильні (змінено 1–2 пункти, переставлено порядок або взято відповідь сусіднього питання).

### Питання з фото білетів

Розпізнані питання зіставлено з файлом і позначено в застосунку тегом «з білетів»:
М1 №6, 10, 13, 21, 22, 24, 25, 29, 32, 39, 46, 48, 49, 50, 69, 77; М2 №4, 11, 15, 16, 19, 41; М3 №4, 7, 23, 26, 27, 28, 35, 39, 48, 57, 59.

Не увійшли питання, відповіді на які у файлі немає: МАГАТЕ, тривалість вступної частини заняття у %, азимут, принцип МГП «гуманізм», «чому командирам важко сформувати групову мотивацію», опис пасивно-агресивного стилю спілкування, ієрархія підрозділів TLP. Питання з розгорнутою відповіддю своїми словами покриваються режимом карток.

## Швидкий старт

Потрібен Node.js ≥ 22.18 (TypeScript-тести запускаються нативно).

```bash
npm install
npm run dev        # http://localhost:5173, перезбирання при змінах
npm run build      # dist/index.html і dist/klsr-quiz.html
```

`dist/klsr-quiz.html` — готовий самодостатній файл: його можна надіслати, скопіювати на телефон і відкрити в браузері. На сайті є посилання «Завантажити офлайн-версію».

## Скрипти

| Команда             | Що робить                                                   |
| ------------------- | ----------------------------------------------------------- |
| `npm run dev`       | Збирання з відстеженням змін і локальний сервер             |
| `npm run build`     | Збирання одного HTML-файлу в `dist/`                        |
| `npm run typecheck` | Перевірка типів TypeScript (strict)                         |
| `npm run format`    | Форматування Prettier                                       |
| `npm test`          | Модульні тести та звірка даних з файлом (`node --test`)     |
| `npm run test:e2e`  | Наскрізні тести Playwright (мобільний і десктопний профілі) |
| `npm run check`     | Усе вищезазначене по черзі                                  |

Перед першим запуском e2e: `npx playwright install chromium`.

## Структура

```
src/
  data/        питання (module1–3.ts), альтернативні формати (variants.ts), набори (index.ts)
  core/        чиста логіка без DOM: rng, раунд, легкі варіанти (distractors.ts), сесія, оцінювання, збереження, changelog
  ui/          контролер (app.ts), компоненти, екрани (views/)
  main.ts      точка входу
  styles.css
scripts/build.mjs   esbuild → один HTML-файл
tests/
  unit/        логіка ядра
  data/        цілісність даних і звірка з source/questions.txt
  e2e/         Playwright, відкриває зібраний dist/klsr-quiz.html
source/questions.txt  текст PDF (pdftotext -layout) — еталон для тестів
```

## Як додати або змінити питання

1. Додайте питання у `src/data/moduleN.ts`: `n` — номер у файлі, `q` — текст питання, `a` — відповідь (масив пунктів; підсписки — `{ title, items }`), `w` — три неправильні варіанти.
2. За потреби додайте формати у `src/data/variants.ts` (`tf`, `term`, `mcq`, `multi`, `order`). Правильна відповідь у них завжди береться з `a`.
3. Оновіть `source/questions.txt`, якщо змінився сам файл питань.
4. `npm test` — тест звірки покаже, якщо текст не збігається з файлом.

## Розгортання на GitHub Pages

1. Створіть репозиторій і завантажте проєкт у гілку `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. Кожен push у `main` запускає [`.github/workflows/ci.yml`](.github/workflows/ci.yml): перевірки → тести → збирання → публікація. Самодостатній HTML також доступний як артефакт `klsr-quiz-offline`.
4. Після першого `npm install` закомітьте `package-lock.json` і замініть у workflow `npm install` на `npm ci`.

> Сайт на GitHub Pages публічний. Переконайтеся, що поширення матеріалів дозволене (на білетах є позначка «Обмежено у розповсюдженні — лише для Збройних Сил України»).

## Технології

TypeScript (strict, без фреймворків) · esbuild · Prettier · Node test runner · Playwright · GitHub Actions / Pages.
Застосунок не має залежностей під час виконання; дані зберігаються лише в `localStorage` браузера.

Параметри для тестів і налагодження: `?seed=123` — відтворюване перемішування; `?alt=1` — частка питань в інших форматах (0…1, за замовчуванням 0.1).
